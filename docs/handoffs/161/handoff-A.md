## Summary

BLOCK. The new "Where a pinned request's detection comes from" section closes most of the prior B2:

- The seam is named: `sent := req`, and `req` is never mutated.
- The identity/covers-target branch now exists, and the within-budget and chunked paths converge on it.
- `pinFallback` is threaded into `callEngineChunked`.
- The corrected `From` is qualified through `resultFrom(model.Auto, detected)`.
- W1 and W3 are fixed.
- The scope limits held.

Checked against the real code, the pseudocode still has two defects that T would encode into RED tests, and the prior B3 is now an outright contradiction:

1. **B1 (new).** Native engine codes produce false corrections. The brief says `detectedSource` returns `ok=false` for "an unrecognized native code (baidu/youdao)" (:235, :19, test :218). It does not. `detectedSource` (`service.go:279-287`) returns `ok=false` only on an auto echo or an error with no attached detection, so Baidu's `jp` comes back `ok=true`. `SameAs("jp","ja")` is false: `canonical("jp")` is unrecognized and stays `jp`. So pseudocode :207 sets `DetectedFrom = "jp"` on every Baidu request of 20 or more code points pinned to Japanese. The same happens for `kor`, `fra` and `spa`. The user sees a false note ("Translated from auto-detected jp"), and the brief's own test :218 contradicts the brief's own algorithm.
2. **B2 (new).** The identity branch reports the wrong `From`. Pseudocode :192 calls `s.identityResult(engineName, req, detected)` and claims "only the detected From differs". But `identityResult` computes `From: s.resultFrom(req.From, detected)` (`service.go:~296`), and for a pinned `req` `resultFrom` returns the pin. In the reported bug (pin `es-MX`, English text, target `en`), the identity result would say `From: es-MX`. The frontend `detectedFrom` (`TranslateWindow.svelte:536`) then feeds `swapPair` the wrong language.
3. **B3 (prior B3, unresolved and now contradicted).** The note never fires in Auto mode. The Reuse map `DetectedFrom` row (:194) and the pseudocode (:201-203) say `DetectedFrom` is "empty always on the non-substituted path". A genuine Auto request is non-substituted. But the Visible-cue section (:165), wireframe state 2(b) (:182) and D's approved design all require the note under an Auto-mode result. As written, #11's Auto detection feedback is deleted with nothing to replace it.
4. **B4 (prior B1, partly unresolved).** Stale superseded text remains at :32, :33, :210 and :236. Commit aed9aad's message says "every stale reference actually removed". It was not.
