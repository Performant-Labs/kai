## Summary

BLOCK. The new mechanism is the right shape and technically viable. On a pinned request of at least 20 code points, the engine is sent `From: auto`, the one call's detection is read back, and it is compared with the original pin using `SameAs`/`Covers`, with no second engine call. It is viable because every registered engine accepts an auto source: `engine.SupportsAutoSource` defaults to true, and Apple returns true (`apple_darwin.go:72`). This resolves prior finding #1 and most of #2.

It still fails the re-review on three counts:

1. **Question 6.** The superseded toast, `Corrected` boolean and `fromLang`-assignment text was added around, not removed. Several of the exact passages the prior review named are still there.
2. **Question 1.** The data flow does not say what happens when the substituted-auto detection covers the target. That is the most likely shape of the reported bug. The within-budget and chunked paths would diverge on it.
3. **Question 2.** The Reuse map still tells the frontend to string-diff against the displayed FROM value, which contradicts criterion (a)4.
