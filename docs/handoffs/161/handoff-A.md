# Handoff-A: Phase 3 - #161 source-lang-correct  (up-front plan review)

**Date:** 2026-09-28
**Branch:** issue-161-source-lang-correct (base 096643a, head 6cdceb2)
**Brief reviewed:** docs/handoffs/161-brief.md   **Reuse map:** the brief's "Reuse map" table   **Wireframe:** docs/handoffs/161/wireframe.html (revision 3, approved) + docs/handoffs/161/handoff-D.md
**Verdict:** BLOCK

## Summary

BLOCK. The frontend half is sound. `translate.sourceAuto` is a new key and does not touch `lang.auto`; `GeneralTab.svelte:79` is its only other use, and it keeps "Auto". The note is a sibling element in the existing note stack, above and outside the result `<textarea>` (`TranslateWindow.svelte:1309-1322`), the same as the phonetic, cancelled and identity notes.

The backend half cannot deliver acceptance criterion (a)1 as planned. The plan gets the pinned-path detection from `detectedSource(res, err)`, with no second call. But on a pinned request, the Apple engine (the one in the bug report) and most other engines report the pin back as `From`. So `detectedSource` returns the pin, and the correction never fires. For a non-chunked request, there is also no point before the engine call where a correction could be decided.

The brief also still contains parts of the superseded toast / `Corrected`-boolean / `fromLang`-reassignment design. T would write tests against a contract that is not settled.
