#161 source-language correction + Auto landmark - wireframe (low-fi)

Translate window only. Two changes: (b) the Auto entry of the source dropdown always keeps the word "Auto" (en-US) / "自动" (zh-CN, the existing lang.auto name) and appends the detection as a clause (sections A, B); (a) when a pinned source is overridden by detection the existing .u-toast announces it (sections C, D, E), and a pin that was right changes nothing (section C, frame "pinned, correct"). Frames are whole windows at the real widths: default 960 px and minimum 780 px (main.go MinWidth). Heights are cut down (the real minimum is 520 px); nothing here depends on height. The open dropdown is drawn as the macOS menu WKWebView shows for a native <select>: ✓ marks the selected entry. The closed select is drawn at the width a native select takes, i.e. its widest option (measured by this page), never less than min-width: 7rem. Language list and order are the real ones (ALL_TRANSLATE_LANGS, frontend/src/constants/lang.ts); names are the real lang.* strings.
Glyphs are Unicode stand-ins (⇄ ⚙ ⧉ ▾ ✓) for the Lucide icons already in the build; nothing new is drawn. = new or changed element (the outline is a wireframe marker, not a style). The grey line under a frame is measured by the page when it loads. Zoom: the buttons at the top right, or the - / + / 0 keys (starts at 150%; #z=1 in the URL starts at 100%).
Default shows 4 per state, which together cover 960/780, light/dark, en-US/zh-CN.

A. The Auto entry across its states (source = Auto)

Single chokepoint: detectedSourceLabel returns t('translate.autoDetected', {lang}) instead of nameOf(detected) + ' (detected)'. When it returns null the entry falls back to langName('auto') = "Auto" / "自动", as today. No other entry is ever relabeled.

A1. No detection yet (window just opened, or text cleared): bare "Auto"; ⇄ disabled (nothing to exchange)

A2. Detected as another language (Spanish text, target English): "Auto — detected: Spanish (Mexico)"

A3. Detected as the target itself (identity, #80): "Auto — detected: English", source text shown with the existing identity note, no toast

A4. Detection unusable / low-confidence: the engine echoed "auto" or reported a native code Covers cannot match (baidu/youdao) — falls back to bare "Auto", no claim, no toast

B. Same states side by side in one open menu, and the pinned entry for comparison

What the first rows of the menu read in each state (en-US / zh-CN). The pinned entry "Spanish (Mexico)" three rows below is never suffixed, so "Auto — detected: Spanish (Mexico)" and the plain pin can no longer be confused.

C. Pinned source: corrected vs. correct (source pinned to Spanish (Mexico), target Chinese / English)

Correction fires only when the whole trimmed text is ≥ 20 code points and the engine reports a recognized detection that differs from the pin (and is not the target, which stays the identity rule). It is decided once, from chunk 1. The toast is fired from the EventTranslateResult handler for the active engine's result carrying corrected: true, via the existing showToast (1.6 s). No call to onLangPicked / learnLangVariant / persistLangs: default_from stays es-MX in settings.

C1. Pinned but correct (Spanish text, pin Spanish (Mexico)): nothing changes — no toast, dropdown untouched, Auto entry bare

C2. Pinned and wrong, OPTION A (recommended, brief's recommendation): dropdown reassigned to the detected language by direct assignment + toast "Source corrected to English"

C3. Pinned and wrong, OPTION B (alternative): dropdown keeps showing the pin; toast only, worded so it explains the mismatch

C4. Pinned and wrong but too short (< 20 code points, "ok thanks" = 9): no correction, no toast, the pin is honored — result stays the echo (unchanged, accepted limitation per the brief)

D. The dropdown opened right after a correction (option A vs option B)

In both options the Auto entry reads bare "Auto" / "自动" (the source is not Auto, so detectedSourceLabel returns null) — it is the fixed landmark the user picks to escape back to Auto. Option A: ✓ on English (the corrected, now-selected value). Option B: ✓ stays on Spanish (Mexico) although the request used English.

E. Source-corrected toast next to the Copied toast (same .u-toast, same 1.6 s, one at a time)

Both go through the one toast state string. A later showToast replaces the text and restarts the 1.6 s timer, so the two pills can never be visible together or stack; the sequence strip shows a Copy click 0.8 s into a correction toast. Pills are shown inline here for comparison; in the window they sit bottom-centre, 20 px up, pointer-events: none.
