#161 source-language note - wireframe (low-fi, revision 3)

Revision 3 (2026-09-28): the Auto entry is relabeled "Detected". Per the principal, the source dropdown's Auto entry (value auto, unchanged) now always reads "Detected" / "自动检测", from a new key translate.sourceAuto. The shared lang.auto ("Auto" / "自动") is not touched, because the General settings tab's interface-language picker (GeneralTab.svelte:79) still uses it and must keep reading "Auto". The label is fixed: it never changes with detection state.
Carried from revision 2 (principal's override): the FROM dropdown never changes on its own. A pinned entry is never reassigned or suffixed. That walks back #11's relabeled Auto row. Revision 1's relabeled Auto row ("Auto — detected: …"), its option A (reassign the pin), its option B, and the correction toast are all dropped. What replaces them is one persistent, muted line in the result pane, "Translated from auto-detected Spanish (Mexico)", shown when the language the engine actually used differs from what the dropdown shows.
Translate window only. Frames are whole windows at the real widths: the 960 px default and the 780 px minimum (main.go MinWidth). Heights are trimmed; nothing here depends on height. The open dropdown is drawn as the macOS menu WKWebView shows for a native <select>. ✓ marks the selected entry. The closed select is drawn at the width a native select takes, which is its widest option (this page measures it), never less than min-width: 7rem. With the Auto entry always reading "Detected", the widest source option is "Portuguese (Portugal)", so the select's width no longer depends on detection. The language list and its order are the real ones (ALL_TRANSLATE_LANGS). Names are the real lang.* strings. Result-pane notes follow the real markup (TranslateWindow.svelte ≈ :1309-1322). Each is u-muted px-4, the first one takes first:pt-4, and they stack above the result textarea.
Glyphs are Unicode stand-ins (⇄ ⚙ ⧉ ▾ ✓) for the Lucide icons already in the build. Nothing new is drawn. = new element (on the note itself: an orange bar at its left edge). = must stay exactly as the user left it (the rule this revision exists to prove). These outlines are wireframe markers, not styling. The grey line under each frame is measured by the page when it loads. Zoom: the buttons at the top right, or the - / + / 0 keys. It starts at 150%; #z=1 in the URL starts it at 100%.
By default each state shows 4 frames, which together cover 960/780, light/dark and en-US/zh-CN.

1. The source dropdown never changes: the Auto entry always reads "Detected", and a pin stays where the user put it

detectedSourceLabel no longer relabels anything. Every language <option> reads langName(value). The Auto entry (value auto) reads t('translate.sourceAuto'), a constant: "Detected" / "自动检测". Nothing about it depends on a result. The four frames per state below show the same menu before and after a result. Only the ✓ position differs, and only because the user picked a different entry.

1b. Source = Auto, result arrived, the engine detected Spanish (Mexico): still "Detected" ✓, with no language name and no suffix. The "Spanish (Mexico)" row stays plain.

1c. Source pinned to Spanish (Mexico), and the English text was translated from auto-detected English: ✓ stays on "Spanish (Mexico)" and nothing moves. The Auto row still reads "Detected".

1d. Every state on one line: the first rows of the menu (en-US / zh-CN)

2. The new persistent result-pane note in its three states

The note is rendered from activeResult.detected_from, which the backend sets only when the engine-used language differs from the request's from. The frontend shows it when that field is non-empty and differs from the displayed FROM value. It stays for as long as that result is showing. It is not a toast, has no timer, and is not clickable. It follows the active engine's result, so switching engines in the pane dropdown can show or hide it. The source pane, fromLang and default_from are never touched.

2a. Not shown: the pin was correct (Spanish text, pin Spanish (Mexico))

2a′. Not shown: nothing translated yet, whatever the source setting

2b. Shown under an Auto-mode result: dropdown "Detected", note "Translated from auto-detected Spanish (Mexico)"

2c. Shown under a pinned-but-wrong result: dropdown still "Spanish (Mexico)", unmoved; note "Translated from auto-detected English"; the result is a real translation, not the old echo

Proposed order: the new note goes first, above phonetic, cancelled and identity. It is about where the text came from, so it heads the stack, and the existing notes keep their current order relative to each other. It takes first:pt-4 as the first line, and the lines after it drop their top inset, as today. The page measures that no note overlaps the next line or the textarea, and that none overflows the pane.
