## Summary

The plan extends the objects in the Reuse map and adds no parallel path. Dependency direction holds: the kind constants move down into `internal/model`, which `engine` and `translate` both already import (`engine.go:11-12`, `model.go:3` imports only `strings`), so `engine.HTTPError.Kind` can name a kind without `engine` importing `translate`. The classifier stays the only classifier, in `translate`, which already imports `engine` for `Translator`, so it can read `*engine.HTTPError`, `engine.ErrAPIKey` and `engine.ErrUnsupportedPair` with `errors.Is/As`. Engines only attach facts. "Configured" stays defined once, by `ValidateRequired`, now also consulted at registration. Sanitizing happens at one emit point (`failurePayload`) and literal-secret redaction at one construction point (`registerEngines`). On the frontend `failureMessage` stays a pure helper in `utils/resultPane.ts` with `t` injected, the component owns the `ShowSettings()` side effect, and the wire name is read as generated (`error_kind`), with no mapping layer.

The choice of `fmt.Errorf("%s: %w", i18n.T(...), err)` over the existing `i18n.Wrap` is right. `i18n.Error.Error()` appends a `\x1f` key/params envelope (`internal/i18n/error.go`), which would leak into the user-visible detail. `i18n.Wrap` has zero production callers, and `"%s: %w"` / `"%s(%s): %w"` is the dominant pattern (`service.go:271,276,387,413`, `configstore/store.go:148-180`).

The warns below are gaps the brief leaves open. Each has a default F and T should apply. None needs a brief amendment.
